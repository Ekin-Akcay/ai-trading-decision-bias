# Conditional quiet-move sample: pre-outcome design

This sampler performs no model calls and calculates no post-entry payoff, excursion or exit statistic. It prepares new historical target intervals for a separately controlled AI-timing experiment. The new 200-call allowance is distinct from the untouched 29 older credits. Final sample/stage counts require the root task's allocation before freezing.

Use SOL, BTC, ETH and DOGE on the common SOL archive's UTC 30-minute t0 grid (:00/:30). The original model-visible snapshot ends at t0−15 minutes and uses `nai.sim.build_snapshot(..., visible_bars=40, hist_bars=200)`. Require 200 complete native 15-minute OHLCV bars, the function's minimum index requirement, and native minute volume throughout the preceding 3,000 minutes. Features may reuse historical information; exact previously used original visible snapshot timestamps/IDs are excluded globally.

Observe native minutes t0 through t0+29 inclusive. Let O be the t0 open and C the t0+29 close. Define move_pct = 100×(C/O−1), and retain absolute move_pct ≥ 0.5×the original snapshot ATR14 percentage. Let observed_volume be those 30 complete minutes' volume sum. Divide it by the median of the 100 non-overlapping 30-minute volume sums immediately preceding t0. Retain volume_ratio ≤0.75 with a strictly positive reference median. Positive moves are quiet rallies and negative moves quiet declines. All these conditioning measurements are known at the proposed entry, t0+30 minutes. No later information is used as a selection feature.

The future trade interval is [t0+30 minutes,t0+150 minutes), with a prospective first-open entry and last-complete-minute close after 120 minutes. At sampling, inspect future timestamps and finite positive OHLC validity only; do not calculate returns, inspect price paths, or write future prices. Require complete minute OHLC coverage. The new trade interval must not intersect any of the 681 prior global exposed intervals, each [old entry−50 hours,old entry+known 6/24/72-hour horizon), reconstructed from the MA-ablation manifest. Also exclude intersection with every one of the 783 proxy targets [proxy entry,proxy entry+4 hours). Intervals are half-open; exact boundary adjacency is permitted. Exclusions apply across assets, and one asset is selected per global event.

First report coverage and gate counts by direction, year and asset, including distinct UTC-day capacity. A fixed seed (2026093017) assigns candidate priorities. Prefer at most one selected event per UTC day, with no selected outcome overlap globally. Balance up/down directions exactly and spread selections across assets and years using only candidate features/timestamps and fixed random priority. If the target count cannot be obtained, report the capacity rather than relaxing exclusions, gates or spacing after seeing outcomes. No future outcome is available to the sampler's allocation procedure.

The root task finalized a maximum of **180 valid calls plus 20 physical retry calls**, without using the older29 credits. Freeze 60 screen opportunities (30 rallies,30 declines), followed by an ordered pool of120 confirmation opportunities per direction if capacity permits. This is300 potential windows, not300 calls. If both directions pass the separately frozen screen, use the first60 confirmation ranks each; if just one passes, use its120; if neither passes, stop. Only120 confirmation decisions may be requested in total. If300 potential windows cannot meet all constraints, deterministically fall back to180 potential windows (60 screen plus60 confirmation per direction), retaining unused budget when one direction fails. There are no newly selected substitute windows after outcome inspection.

The deterministic allocator assigns fixed random priorities (seed2026093017) after sorting candidates by t0 and asset. Select screen, confirmation-core, then confirmation-extension tiers in that order. Screen direction/asset quotas for SOL/BTC/ETH/DOGE are up8/8/7/7 and down7/7/8/8, giving15 total per asset. Each confirmation tier has15 of each direction per asset, so the first60 ranks per direction and complete120 ranks per direction are both asset-balanced. At each pick, choose the direction/asset stratum with the fewest currently available distinct days per outstanding slot; within it prefer the least represented year in that tier, then smallest fixed random priority, then timestamp/asset. Block the chosen UTC day across all assets and every candidate whose120-minute outcome overlaps it. This uses only coverage, timestamps and pre-entry gate information. No result-based selection is available. Potential confirmation rows receive their direction-specific rank after tier ordering and random-priority ordering within each tier.

The canonical manifest is `fresh_windows.json`, with a `cases` list. Every record contains only identifiers, timestamps, pre-entry gate metadata and coverage information, plus case_id, stage, selection_tier and confirmation_rank. Manifest and companion candidate/exclusion files carry input/script hashes. No model call or post-entry scoring is part of this sampler.

This historical sample is fresh with respect to the listed specific target exposures, not guaranteed unknown to model training. Known past inputs can overlap prior studies. One event per day reduces immediate dependence but does not create independent market regimes; later inference must retain calendar dependence. Conditioning creates a quiet-move population and cannot establish all-market performance.
